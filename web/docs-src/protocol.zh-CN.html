线上协议分为两层：一组精简的 HTTP/WebSocket 控制面，以及一条流式数据面。proto/sync.proto 与 JSON 线上格式保持一致。

控制面端点

端点作用
GET /api/v1/records拉取记录，支持 kind、limit 与 before。
POST /api/v1/records/text保存文字记录并广播。
POST /api/v1/records/blob流式上传图片/文件，携带 kind、name、mime 与可选的 X-Blake3。
GET /api/v1/blobs/{id}下载 blob，支持 HTTP Range。
DELETE /api/v1/records/{id}删除自己的记录与 blob。
GET /api/v1/relay/{session_id}使用 X-Session-Ticket 中继字节流；连接被劫持后双向转发。

P2P 会话

  1. 控制面给两端各签发一张一次性 32 字节 票据，并下发候选地址池。
  2. 双方用系统证书完成双向 TLS。
  3. 接收方按 300 ms 一档并发探测 LAN/VPN 候选。
  4. 直连成功后传输固定 49 字节 帧。
  5. 1.2 秒内无人应答时，服务端用 io.Copy 中继同一会话；15 秒配对超时。
注意

中继只做透明字节转发。端到端保护仍在两端之间，服务端不会把流转写进磁盘。

Blob 与记录

  • POST /api/v1/records/blob 流式处理请求体，不把整个文件读进内存。
  • GET /api/v1/blobs/{id} 在两端都支持 Range 续传。
  • 文字上限 64 KiB，存入 SQLite。
  • 删除仅限所有者，没有管理员覆盖。

帧格式

数据面使用固定 49 字节 帧；Android 额外携带 BLAKE3 校验。中继复用同一套帧流，因此客户端无法从负载判断字节是直连还是经服务端转发。
