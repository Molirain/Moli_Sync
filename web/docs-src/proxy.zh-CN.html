MoliSync 只信任来自配置网段的反向代理身份头。代理必须先校验证书、清除入站身份头，再写入新的校验结果。

信任顺序

  1. 终止 TLS，并请求客户端证书。
  2. 校验证书链，必要时检查吊销状态。
  3. 清除入站 X-Client-* 头。
  4. 用代理自身的变量写入校验结果、指纹与 Subject。
  5. 转发 WebSocket Upgrade，并关闭请求/响应缓冲。

Nginx 示例

proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection $connection_upgrade;
proxy_request_buffering off;
proxy_buffering off;

proxy_set_header X-Client-Verify $ssl_client_verify;
proxy_set_header X-Client-DN $ssl_client_s_dn;

# 关键：nginx 没有 SHA-256 变量，$ssl_client_fingerprint 是 SHA-1（40 位），
# 服务端会以 invalid_client_fingerprint 拒绝，因此转发整张证书让服务端自己算。
proxy_set_header X-Client-Fingerprint "";
proxy_set_header X-Client-Cert $ssl_client_escaped_cert;

对应服务端配置：MOLISYNC_PROXY_CERT_HEADER=X-Client-Cert，并把同一个 CA 证书挂进容器后设置 MOLISYNC_PROXY_CLIENT_CA_FILE（可选但强烈建议，服务端会再验一次签发链）。

注意

proxy_set_header X-Client-Fingerprint ""; 会把指纹头清空。如果只写这一行却不转发 X-Client-Cert，服务端拿不到任何指纹：P2P 只能走中继（客户端会显示"经服务端中继传输"）。

能直接给出 SHA-256 的代理不需要 cert_header：Caddy 用 {http.request.tls.client.fingerprint}（SHA-256）即可。

映射头名称

告诉控制面应该读取哪些头：

变量示例值
MOLISYNC_PROXY_VERIFY_HEADERX-Client-Verify
MOLISYNC_PROXY_FINGERPRINT_HEADERX-Client-Fingerprint
MOLISYNC_PROXY_CERT_HEADERX-Client-Cert（可选，转发整张证书）
MOLISYNC_PROXY_CLIENT_CA_FILECA 路径（可选，校验证书头）
MOLISYNC_PROXY_DN_HEADERX-Client-DN

网络边界

只有代理与控制面加入 molisync-internal（示例子网为 172.28.0.0/24）。MOLISYNC_PROXY_TRUSTED_CIDRS 应尽量收紧到该网络。

警告

能进入受信网络的任何进程都能伪造身份头。不要把 Go 服务直接暴露到公网，也不要让客户端加入该网络。

检查清单

  • 客户端证书校验已开启，并用受信证书验证过。
  • 边缘已清除入站 X-Client-* 头。
  • MOLISYNC_PROXY_TRUSTED_CIDRS 只匹配代理网络。
  • WebSocket Upgrade 与流式转发（无缓冲）已验证。
  • 健康检查仍指向真实监听端口。
