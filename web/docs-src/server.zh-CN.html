控制面是一个静态编译的 Go 服务，以 distroless 容器分发。它假定由反向代理终止 mTLS，自身从不发布 9520 端口。

环境要求

  • Linux 主机，Docker 24+（使用示例 Compose），或 Go 1.22+ 从源码构建。
  • 能校验证书链的反向代理：Nginx、Nginx Proxy Manager 或 Caddy。
  • 一个只允许代理与控制面加入的私有 Docker 网络。

拉取并启动

docker pull ghcr.io/molirain/molisync-server:latest
cp docker-compose.example.yml docker-compose.yml
docker compose up -d
docker compose ps

镜像支持 linux/amd64 与 linux/arm64，以 nonroot 运行，内部没有 shell 或包管理器。

警告

示例 Compose 不会发布 9520 端口。不要添加宿主机端口映射；把你现有的反向代理加入 molisync-internal 网络即可。

配置

所有设置都能用环境变量传入，也可以使用 YAML；同名环境变量优先于文件。

变量作用
MOLISYNC_SERVER_LISTEN监听地址。镜像内默认 0.0.0.0:9520。
MOLISYNC_PROXY_TRUSTED_CIDRS允许断言身份的代理网段，必须与 Compose 子网一致。
MOLISYNC_PROXY_VERIFY_HEADER携带校验结果的头。
MOLISYNC_PROXY_FINGERPRINT_HEADER携带证书指纹的头。
MOLISYNC_PROXY_DN_HEADER携带证书 Subject 的头。
MOLISYNC_AUTH_DEVICE_ID_SOURCEfingerprint（推荐）或 dn_cn。
MOLISYNC_STORAGE_DATA_DIRSQLite 与 blob 根目录，默认 /var/lib/molisync。
MOLISYNC_STORAGE_MAX_ITEM_BYTES单个 blob 上限，默认 64 MiB。
MOLISYNC_LOG_LEVEL / ..._FORMATdebug|info|warn|error 与 json|text。

健康检查与数据

镜像健康检查调用二进制自带的 -healthcheck-url，探测 http://127.0.0.1:9520/healthz。如果修改了监听端口，Compose 的健康检查也要一起改。

记录与 blob 都存放在 molisync-data 卷中。备份时请同时复制 SQLite 数据库与 blobs/ 目录；删除卷就等于删除全部同步记录。

本地构建

cd server
docker build -t molisync-server:dev .
docker run --rm -p 127.0.0.1:9520:9520 \
  -e MOLISYNC_PROXY_TRUSTED_CIDRS=127.0.0.1/32 \
  molisync-server:dev
