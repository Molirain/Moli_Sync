把控制面当作有状态服务来运维：一个数据卷、一个窄网络，以及一个独占信任边界的反向代理。

数据与备份

  • molisync-data 卷保存 SQLite 元数据与 blobs/ 目录。
  • 记录不会自动过期，目前也没有配额。
  • 只有发送者能删除记录。
  • 备份时请同时复制数据库与 blob 目录，最好在服务停止或静默时进行。

日志与健康检查

MOLISYNC_LOG_LEVEL 支持 debug、info、warn、error；MOLISYNC_LOG_FORMAT 可选 json 或 text。镜像内没有 curl，因此容器通过服务端二进制探测 /healthz。

加固清单

  • 容器以 nonroot 运行，根文件系统只读，不添加 capabilities，并启用 no-new-privileges。
  • 只有代理加入 molisync-internal；9520 端口不对外发布。
  • MOLISYNC_PROXY_TRUSTED_CIDRS 尽量收紧。
  • 客户端私钥留在操作系统证书存储中。
  • Android 强制 HTTPS，并支持固定私有 CA。

升级与版本号

docker compose pull
docker compose up -d
docker compose ps

三端共享「主.次」版本号，补丁号各自独立。发布标签按组件命名：server-v0.5.1 只构建服务端镜像，desktop-v0.5.1 只发布便携版，android-v0.5.1 只发布 APK；没有全局 v* 标签，因此修一端不会连带发布全量。

镜像标签包括 latest、X.Y.Z 与 sha-<commit>。需要可复现的发布时请固定版本标签，并在升级前备份数据卷。服务端每 12 小时自查一次 server-v 发布，并通过 /api/v1/me 把结果转达给客户端，由客户端提示“服务端需要升级”。

使用统计

  • 口径：每台设备**首次**连上服务端时上报一次，计数 +1，之后重连不再上报；没有周期心跳，也没有客户端埋点。
  • 事件只含「部署内唯一的哈希 ID + 平台 + 版本」。该 ID 由「部署 ID + 盐化设备键」派生，跨部署不可关联，Worker 拿不到证书指纹、设备名或 IP。
  • 计数端是项目自建的公开端点 statistics-api.molirain.com（Cloudflare Worker + D1，部署在独立仓库）。
  • GET /stats 需要 ADMIN_TOKEN，未配置时返回 503；?format=text 给出安装数、部署数与平台分布。
  • 「人数」用 deployments 近似（一人一套自建服务器）；installations 是设备数，同一人多端会偏高。
  • telemetry.endpoint 默认为空即关闭；MOLISYNC_TELEMETRY_ENABLED=false 可彻底禁用。

已知限制

  • 没有自动清理，也没有配额。
  • 升级提示依赖 GitHub Releases 的匿名读取，仓库必须公开，否则客户端静默跳过。
  • 端到端 P2P 仍需真实网络回归测试。
  • 仓库尚未声明全局许可证。
